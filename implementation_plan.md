### WG-129 — [BUILD] Adopt baseline BASE-039's caller reproduction proof for production deploys

- Dependency: Wizard-Gang/baseline BASE-039 merged at `1493de4ae8b1f43f23559b210d047a288b00fcf1`.
- Why: BASE-039's `deploy-worker.yml` `verify` job no longer re-runs `npm run check`. It accepts only proof from the Actions API that the caller already ran it: the `deploy-production` job must need, directly or through other needs, exactly one job that sets up Node from `.node-version` and runs `npm ci` then `npm run check` at the run's own commit, with no `continue-on-error`, no step-level `if:` and no checkout ref other than `github.sha`, `github.ref` or `github.event.pull_request.head.sha || github.sha`. Today's `ci.yml` fails that rule: the `release` job repeats the check `verify` already ran and checks out a ref built from a dispatch input. The run must also be at the tag commit, so the `main` dispatch that recovers an older tag can no longer pass.
- Scope: Re-vendor `platform/` and `platform/vendor.lock.json` from `1493de4` with baseline `npm run vendor:lock`, and pin CI's `deploy-production` call to the same commit. Drop `npm ci` and `npm run check` from the `release` job, which checks out the run's own commit and keeps verifying the tag identity and publishing or verifying the immutable Release before the deploy call. Remove the `release_tag`/`expected_commit` dispatch inputs and the recover-from-`main` path with its tests. A dispatch at a release tag ref reruns that tag (rollback, as baseline `platform/deploy/README.md` describes); it verifies, never creates, the Release. Grant `deploy-production` `actions: read` and `contents: read`. Update the release and deployment-boundary tests and README Deployment. No version change.
- Acceptance: `callerReproduction` from the vendored `platform/deploy/evidence.mjs`, run with `node -e` against the new `ci.yml` and pin, returns job `verify` with no failures. `npm run check` passes, including `pin` and the deployment-boundary tests.
- Validation: Pinned `npm ci`, the `callerReproduction` check, focused release-tag and deployment-boundary tests, canonical `npm run check`, `npm run audit:dependencies`, `git diff --check`, exact-head CI and post-merge CI. No tag, Release, deployment, secret, DNS or settings change.
