# Implementation plan

## Open tasks

### WG-103 — [UI] Rebuild the site mobile-first on one dark design system

- Dependency: WG-102 plan-only queue publication has merged; preserve the static React/TypeScript shell, typed page registry, navigation and preference contracts, product previews, Worker, CSP, and release/deployment authorities.
- Why: At phone widths the home Industries grid collapses into an implicit 0px column (one card renders a letter per line and grows past 1,200px), the preferences panel opens off the left edge of the screen, footer contact links run together, Solutions card headings fall back to browser-default margins, and case-study tag lists show stray bullets. The stylesheet is a desktop-first max-width cascade with duplicated and dead rules, competing type treatments (all-caps mono labels beside the sans interface, three different chip styles) and three accent hues.
- Scope: Rewrite `src/styles/tokens.css` and `src/styles/globals.css` mobile-first with `min-width` breakpoints on one dark zinc palette, one accent and one interface typeface; keep the mono face for machine values and the product recreations. Restyle the shared chrome (sticky header, overlay mobile menu, in-viewport preferences panel, footer), every canonical page, and one shared card, chip, button and link vocabulary. Lead the home page with the selected projects, then industries and integrations. As the owner directed, reduce the Solutions hero lede to one sentence that frames the page as solutions, dropping the trailing "Below is what it does…" sentence. Keep the product preview recreations and their motion contract intact. Remove dead selectors. Move the light preference palette onto the same system, align the browser mobile-menu breakpoint and theme-color metadata, and update the README and information-architecture presentation notes. Retire this task into the shared permanent empty queue.
- Non-goals: Beyond that lede, do not add routes, content claims, dependencies, fonts, client hydration, inline styles or inline scripts; do not change preference storage, translation semantics, the CSP, Worker behavior, the package version, a release, or production.
- Acceptance: At 320, 375, 414, 768, 1024 and 1440px, and with 200% text, every canonical page reports zero horizontal overflow and no collapsed grid tracks; the mobile menu and preferences panel stay inside the viewport; keyboard, Escape and no-JavaScript navigation behavior is preserved; dark and light palettes pass the contrast gate; `npm run check` and exact-head CI pass; one WG-103 squash commit lands on main with green post-merge CI and branch cleanup.
- Validation: Pinned npm ci, focused accessibility, frontend-authority, navigation, browser-behavior and documentation tests, canonical credential-free check, browser review of every canonical page at the widths above in both themes and at 200% text, committed-range whitespace check, exact-head required CI, post-merge CI, history and branch cleanup.
- Authorities: AGENTS.md, README.md, docs/INFORMATION-ARCHITECTURE.md, docs/ACCESSIBILITY.md, src/styles/tokens.css, src/styles/globals.css, src/components/SiteChrome.tsx, src/pages/, src/browser/navigation.ts, tests/accessibility-contract.test.mjs, tests/frontend-authority.test.mjs.
